## 1. ВВЕДЕНИЕ И ТЕКУЩИЙ СТАТУС ПРОЕКТА

### 1.1. Что уже реализовано и работает на боевом VPS (`livkamarket.app`):
1. **База данных PostgreSQL & Redis:** таблицы пользователей бота (`users`), API-ключей (`api_keys`), рефералов (`referrals`), а также таблицы сайта (`site_users`, `site_sessions`, `products`, `orders`).
2. **Security Gateway (FastAPI):**
   - Проксирование в OmniRoute (`/v1/chat/completions`) со стримингом и проверкой API-ключей.
   - Эндпоинт верификации IP (`/miniapp/api/verify-ip`) с anti-fraud (`ip-api`) и обходом для админов.
   - Эндпоинт профиля для Mini App (`GET /miniapp/api/user-profile`).
   - Валидация подписи Telegram Login Widget (`POST /api/auth/telegram/validate`).
   - Внутренний приём уведомлений об оплате (`POST /internal/orders/notify`) с отправкой HTML-чеков пользователям и админам.
3. **Маркетплейс (`LIVKAMARKET-site`):**
   - Развернут в Docker на базе обновленной архитектуры `site2`.
   - Векторные карточки товаров (`product-art.tsx`), умный Telegram Login Widget без ошибок «Bot domain invalid».
   - Внутренний эндпоинт привязки заказов: `POST http://site:3000/api/internal/orders/claim`.
4. **Caddy Reverse Proxy:** Автоматический TLS Let's Encrypt для `livkamarket.app` и `api.livkamarket.app`.

## 3. РОУТЕР ЗАКАЗОВ: `app/bot/routers/orders.py`

Файл подключается в диспетчер бота `app/bot/routers/__init__.py`.

### 3.1. Команда `/claim <secret>` (Привязка анонимного заказа)
* **Назначение:** Если пользователь оплатил товар на сайте без авторизации через Telegram, сайт выдал ему 6-значный буквенно-цифровой секрет заказа (поле `orders.secret`). Команда позволяет привязать этот заказ к текущему Telegram-аккаунту и моментально получить реквизиты.
* **Синтаксис:** `/claim <secret>` (например, `/claim A9F21C` или `/claim 031337`). Также бот должен корректно реагировать на ввод секрета в диалоге через FSM.
* **Логика работы:**
  1. Бот парсит аргумент команды. Если секрет не передан:
     *«ℹ️ Введите секретный код заказа в формате: <code>/claim XXXXXX</code>\nКод указан на странице успешной оплаты на сайте livkamarket.app»*.
  2. Бот отправляет асинхронный HTTP-запрос к сайту:
     - **URL:** `http://site:3000/api/internal/orders/claim`
     - **Метод:** `POST`
     - **Заголовки:**
       - `Content-Type: application/json`
       - `X-Internal-Secret: settings.internal_secret`
     - **Тело запроса:**
       ```json
       {
         "telegramId": 1304771090,
         "secret": "A9F21C"
       }
       ```
  3. **Обработка ответа сайта:**
     - **`HTTP 200 OK` (Заказ успешно привязан):**
       Сайт возвращает:
       ```json
       {
         "ok": true,
         "order": {
           "orderNo": 10482,
           "productTitle": "ChatGPT Pro (1 месяц)",
           "credentials": "LOGIN = user@mail.com\nPASS = SuperSecret123"
         }
       }
       ```
       Бот отправляет пользователю карточку заказа:
       ```html
       ✅ <b>Заказ #10482 успешно привязан к вашему аккаунту!</b>

       📦 <b>Товар:</b> ChatGPT Pro (1 месяц)

       🔑 <b>Данные для доступа:</b>
       <pre><code>LOGIN = user@mail.com
       PASS = SuperSecret123</code></pre>

       <i>Нажмите на блок с данными, чтобы скопировать. Реквизиты также всегда доступны по команде /orders.</i>
       ```
     - **`HTTP 404 Not Found`:**
       *«❌ Заказ с таким секретным кодом не найден или уже был привязан к другому аккаунту. Проверьте код и попробуйте снова.»*
     - **`HTTP 401 / 403`:**
       Логирование критической ошибки внутреннего секрета шлюза, пользователю: *«⚠️ Сервис временной привязки недоступен. Пожалуйста, обратитесь в поддержку.»*

### 3.2. Команда `/orders` и кнопка меню «📦 Мои заказы»
* **Назначение:** Просмотр списка всех купленных товаров пользователем.
* **Логика:**
  1. Запрос к сайту: `GET http://site:3000/api/internal/orders/user/{telegram_id}` с заголовком `X-Internal-Secret`.
  2. Если заказов нет:
     *«У вас пока нет купленных товаров.\nВы можете приобрести подписки и ключи в нашем маркете livkamarket.app»* (с инлайн-кнопкой WebApp «🛍️ Открыть маркет»).
  3. Если заказы есть: вывод списка последних заказов со статусом `delivered` и возможностью нажать на конкретный заказ для повторного просмотра логина/пароля.

## 4. НОВАЯ МОДЕЛЬ ТРИАЛА: 500K ТОКЕНОВ И СИСТЕМА УДЕРЖАНИЯ (ХОЛД)

### 4.1. Изменение лимита токенов
В `app/core/config.py`:
```python
trial_tokens_limit: int = Field(500_000, alias="TRIAL_TOKENS_LIMIT")
```
Всем новым пользователям при активации триала лимит ключа устанавливается ровно в `500 000` токенов.

### 4.2. Механика удержания (Холд 24–72 часа)
Цель: обеспечить реальную ценность для рекламодателей и каналов-спонсоров. Пользователь не получает бесплатные токены моментально, а ожидает завершения холд-периода, сохраняя активную подписку на каналы.

#### 1. Модель данных (`app/db/models.py`):
В таблицу `users` добавляются поля:
* `trial_status`: Enum (`none`, `pending`, `active`, `expired`, `rejected`).
* `trial_requested_at`: `DateTime(timezone=True)` — время прохождения всех верификаций и запроса триала.
* `trial_unlock_at`: `DateTime(timezone=True)` — время, когда триал будет разблокирован (`trial_requested_at + timedelta(hours=settings.trial_hold_hours)`).

В `app/core/config.py`:
```python
trial_hold_hours: int = Field(48, alias="TRIAL_HOLD_HOURS")  # По умолчанию 48 часов (2 дня)
```

#### 2. Поведение при завершении верификации:
После прохождения онбординга (Язык $\rightarrow$ Контакт $\rightarrow$ ОП $\rightarrow$ IP):
1. Статус пользователя устанавливается в `UserStatus.PENDING_TRIAL`.
2. Фиксируется `trial_unlock_at = now() + 48 часов`.
3. Бот отправляет сообщение:
   ```html
   ⏳ <b>Заявка на триальный доступ принята!</b>

   🎁 <b>Ваш пакет:</b> 500 000 токенов к Gemini 2.5 Flash / Pro
   🕒 <b>Активация через:</b> 48 часов ({unlock_date_formatted} МСК)

   ⚠️ <b>Важно:</b> Не отписывайтесь от каналов-спонсоров до момента активации, иначе заявка будет аннулирована.

   Мы пришлем вам уведомление и готовый API-ключ сразу по истечении таймера!
   ```

#### 3. Фоновый планировщик активации (`app/services/trial_worker.py`):
Каждые 5 минут периодическая фоновая задача (asyncio task в жизненном цикле бота):
1. Ищет пользователей со статусом `pending` и `trial_unlock_at <= now()`.
2. Для каждого кандидата проверяет:
   - Подписан ли пользователь на все обязательные каналы-спонсоры (`bot.get_chat_member`).
3. **Если подписки на месте:**
   - Генерирует ключ через `ApiKeyService.create_trial_key(user_id, tokens_limit=500_000)`.
   - Переводит пользователя в статус `UserStatus.ACTIVE_TRIAL`.
   - Отправляет уведомление пользователю:
     ```html
     🎉 <b>Твой триальный доступ активирован!</b>

     🔑 <b>Ваш API-ключ:</b>
     <pre><code>{raw_api_key}</code></pre>

     🌐 <b>Base URL для Cursor / Zed / Claude Dev:</b>
     <code>https://api.livkamarket.app/v1</code>

     📊 <b>Баланс:</b> 500 000 токенов
     Подробная инструкция по настройке доступна в меню «🔑 Мой ключ».
     ```
4. **Если пользователь отписался от спонсоров:**
   - Отправляет уведомление:
     *«⚠️ Мы не смогли активировать ваш триал, так как вы отписались от одного из каналов-спонсоров. Подпишитесь снова и нажмите кнопку проверки.»*

## 5. МОДУЛЬ ОБЯЗАТЕЛЬНОЙ ПОДПИСКИ (ОП / SPONSORED CHANNELS)

### 5.1. Модель данных `SponsoredChannel` (`app/db/models.py`)
```python
class SponsoredChannel(Base):
    __tablename__ = "sponsored_channels"

    id: Mapped[int] = mapped_column(Integer, primary_key=True, autoincrement=True)
    title: Mapped[str] = mapped_column(String(255), nullable=False)
    channel_id: Mapped[int] = mapped_column(BigInteger, unique=True, nullable=False)  # Например -1001234567890
    invite_link: Mapped[str] = mapped_column(String(512), nullable=False)
    is_active: Mapped[bool] = mapped_column(Boolean, default=True, nullable=False)
    created_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now())
```

### 5.2. Проверка статуса подписки (`app/services/subscription_service.py`)
Функция `check_user_subscriptions(bot: Bot, user_id: int) -> tuple[bool, list[SponsoredChannel]]`:
* Запрашивает все активные каналы `is_active == True`.
* Для каждого канала вызывает:
  ```python
  member = await bot.get_chat_member(chat_id=channel.channel_id, user_id=user_id)
  is_subscribed = member.status in ("member", "administrator", "creator")
  ```
* Если бот не является админом канала или чат недоступен — ошибка логируется, но пользователь не блокируется.
* Возвращает `(True, [])` если все подписки подтверждены, либо `(False, [неподписанные каналы])`.

### 5.3. Экран подписки в боте
Клавиатура формируется динамически: по кнопке на каждый канал + кнопка «✅ Проверить подписку» (`CallbackQuery: check_subs`).

### 5.4. Управление спонсорами через `/admin`
В `app/bot/routers/admin.py` добавляется секция «📢 Каналы-спонсоры»:
* Просмотр списка активных спонсоров.
* Добавление канала: отправка ID или пересылка поста из канала, ввод ссылки-приглашения.
* Включение/выключение проверки канала без удаления.
* Удаление канала.

## 6. ЗАЩИТА ТЕЛЕФОНА (SEND CONTACT)

Подтверждение номера телефона — обязательный шаг перед постановкой на холд триала:
1. Кнопка `KeyboardButton(text="📱 Поделиться контактом", request_contact=True)`.
2. **Обязательная валидация в хэндлере:**
   ```python
   if message.contact.user_id != message.from_user.id:
       await message.answer("❌ Запрещено отправлять чужой контакт из телефонной книги.")
       return
   ```
3. Проверка уникальности номера по базе (1 номер = 1 аккаунт).
4. Номер сохраняется в `users.phone` в формате `+7999...` / `+380...`.

## 7. ТЕСТОВЫЙ ЗАКУП И КРИТЕРИИ ПРИЁМКИ (DEFINITION OF DONE)

### 7.1. Сквозной тестовый сценарий (E2E Test)

| Этап | Действие | Ожидаемый результат |
|---|---|---|
| **1. Старт** | Отправка `/start` новым пользователем | Выбор языка $\rightarrow$ Оферта $\rightarrow$ Запрос контакта. |
| **2. Контакт** | Отправка чужого контакта | Ошибка: отклонён. Отправка своего контакта $\rightarrow$ принято. |
| **3. ОП** | Проверка спонсорских каналов | Бот требует подписку. После подписки пускает на Mini App IP. |
| **4. IP-чек** | Прохождение IP-чека в WebApp | Антифрод одобряет IP, статус `PENDING_TRIAL`, таймер на 48ч. |
| **5. Холд** | Срабатывание воркера через N минут/часов | Автоматический пуш с готовым API-ключом на 500 000 токенов. |
| **6. Запрос** | Тестовый запрос в `api.livkamarket.app/v1` | 200 OK, стриминг ответа нейросети, списание токенов. |
| **7. Маркет** | Покупка на сайте `livkamarket.app` | Чек моментально прилетает в Telegram в личку покупателю и в админ-чат. |
| **8. Claim** | Команда `/claim <secret>` в боте | Анонимный заказ привязывается к аккаунту и выдаёт реквизиты. |
